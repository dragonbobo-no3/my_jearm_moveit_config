## 可复用边界，不是 MoveIt 启动参数

[现有运行器](run_jeserver_v2_sdk_probe.sh) 使用独立 user/mount/IPC/network/PID
命名空间、私有共享内存、只读根目录与固定输入挂载；屏蔽实体设备和实体模型，
只复制仿真资源到临时目录。[C 加载器](jeserver_v2_sdk_probe.c) 在 dlopen 前复核
命名空间、仅回环网卡、无有效 capabilities、固定哈希和仿真配置，初始化后再次核对
simulation=1、单臂、七轴。新测试必须保留这些拒绝条件及外层超时。

这不等于独立机器的 CPU/实时调度资源隔离，也不消除与宿主进程争用资源的可能。
优先在具备厂商许可、模型及受控实时权限的独立测试环境准备复现。

现有 `--writer-exit-virtual` 测的是正常保持与退出，不注入启动前 STOP；
`--teach-*-virtual` 测的是点动停止，不覆盖本次首次保持场景。
本方案不是把 MoveIt 的 `mode:=real` 改成 `mode:=sim`，不接入生产 ROS/ZMQ 端口。

## 拟新增对照（尚未实现）

每个用例使用全新沙箱、全新 SDK 初始化与私有共享内存，不在故障进程中复位重跑。
共同准备：确认仿真、唯一机器人和七轴；仅虚拟使能；初始化同一日志队列；
记录使能结果、实际关节、power、move state、driver/move error 与单调时间。
非有限反馈、非健康空闲、参数或隔离条件异常时，在 Start 前退出。

| 用例 | 唯一有意差异 | 需要记录的观察 |
|---|---|---|
| A：无显式 STOP | 本次初始化后不主动调用任何 STOP | 首次 Start 及立即一次 Joint 的返回、前后状态与时间 |
| B：启动前 STOP | 健康空闲时仅调用一次公开 RobotStop(0) | STOP 返回和调用后状态；再记录同样的首次 Start/Joint |

- A 只能称为“无显式 STOP”，不能凭状态 0 宣称内部订单一定为空。
- B 的 RobotStop 返回 0 只记录调用结果，不将其当作订单持续待处理的动态证明。
  如 STOP 后已不是健康空闲，则记录“启动前条件不成立”，不强行启动。
- 固定首次目标为当前七轴位置、命令时间 0.01；Start 参数与诊断桥保持一致。
  Start 非零则不发 Joint。Start 返回 0 后不增加任意等待、不重试 Joint；
  先记录首次调用结果，再做有界只读状态观察。
- 必须区分：首次 Joint 返回 7、首次 Joint 返回 0 后才出现 7、其他错误、
  Start 超时、前置条件失败。Joint 返回 0 本身也不能证明接收或后续执行成功。
- 记录关节是否改变，但本实验不发非保持目标；不测试示教器并发、不点动、不接管。
- 结果采集与清理分开标记，清理调用及其产生的状态不得回填成首次故障证据。
  不调用 get_robot_order1 来查询或清空订单；不清错、不恢复、不重启伺服。
  SDK 保留到私有进程退出；清理被外层超时约束，退出不是正常 writer-exit 验收。

若 B 能稳定重现而 A 不能，只证明受控 STOP 可导致该启动失败，仍不能确定实体事件
中的 STOP 来源。若两者均异常或表现不同，应保留原始结果，不通过改延时、重试或
豁免状态 7 来让测试通过。隔离复现通过也不自动授权修改或重启实体控制链。
